# ADR 0002: Hardware Abstraction Layer (HAL)

**Date**: 2026-07-27
**Status**: Accepted

## Context
The SmartFlow firmware currently mixes hardware-specific calls (`digitalWrite`, `analogRead`, GPIO pin macros) directly into business logic and safety checks. This tight coupling makes the code impossible to unit test off-hardware, difficult to read, and risky to modify, as a change to a pin assignment could break the core safety loop.

## Decision
We will implement a dedicated Hardware Abstraction Layer (HAL) under `firmware/master_node/src/hal/`. 
All raw hardware interaction must be encapsulated behind capability interfaces (e.g., `PumpHal::enable()`, `UltrasonicHal::readDistance()`). No layer above the `drivers/` layer is permitted to know about GPIO pins, UART registers, or specific microcontrollers.

## Consequences
**Positive**: 
- Code becomes strictly decoupled and highly testable. 
- We can implement "mock" HALs to run unit tests on a standard PC without an ESP32.
- Future hardware revisions (e.g., migrating from ESP32 to STM32) will only require rewriting the HAL, leaving business logic untouched.

**Negative**:
- Adds slight overhead in function calls and complexity in the build system.
